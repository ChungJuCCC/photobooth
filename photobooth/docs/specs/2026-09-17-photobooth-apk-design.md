# 셀프 포토부스 APK — 설계

작성일 2026-09-17 · 상태: 구현됨 (실기기 검증 전) · 설치는 docs/SETUP.md

## 1. 목표

세로로 세운 안드로이드 태블릿에서 손님이 직접 사진을 찍고, QR로 사진과 타임랩스 영상을 받아가는 포토부스 앱.
손님 데이터는 업로드 완료 후 24시간이 지나면 받을 수 없고, 1시간 안에 서버에서도 지워진다.
운영자는 원하는 프레임 PNG를 태블릿에서 바로 등록하고, 등록한 프레임은 모든 태블릿에 공유된다.

### 확정 사항

| 항목 | 결정 |
|---|---|
| 기기 | 안드로이드 태블릿, **세로 거치** |
| 앱 | 기존 웹앱을 Capacitor로 감싼 APK |
| 배포 | GitHub Releases 링크로 직접 설치 |
| 촬영 | 6장 촬영 → 4장 선택 |
| 타임랩스 | 촬영 전체를 3배속, 약 5초 (MP4) |
| 레이아웃 | 세로 4컷(591×1772), 바둑판(1080×1200) |
| 저장소 | Supabase (카드 등록 없음) |
| 손님 페이지 | Vercel 정적 페이지 |
| 보관 | 업로드 완료 후 24시간 |
| 인터넷 끊김 | 기기에 보관 후 자동 재업로드 |
| 프레임 등록 | 숨은 버튼 + PIN, 비율이 맞으면 자동 크기 맞춤 |
| 손님 페이지 내용 | 사진 · 타임랩스 · 남은 시간 |
| 규모 | 월 500팀 이하 |

### 이번 범위에서 제외

- iPad / iOS
- Play 스토어 배포
- PNG 투명 영역 자동 인식(규격 고정이므로 불필요)
- 촬영 기록 통계, 운영자 대시보드
- 결제·인쇄

## 2. 구조

```
┌───────────────────────────┐        ┌────────────────────────────────┐
│ 안드로이드 태블릿 (APK)    │        │ Supabase                        │
│                           │        │                                │
│ 촬영 → 선택 → 합성         │ ─────▶ │ Edge Function                   │
│ 타임랩스 생성              │ 업로드  │   create-upload   업로드 허가     │
│ 업로드 대기열(오프라인)     │  허가   │   complete-upload 완료 기록       │
│ 프레임 캐시                │        │   get-session     다운로드 허가   │
│ 관리자 모드(PIN)           │ ◀───── │   list-frames     프레임 목록     │
└───────────────────────────┘ 프레임  │   manage-frames   프레임 관리     │
             │                        │   cleanup         만료 파일 삭제  │
             │ QR                     │                                │
             ▼                        │ Storage                         │
┌───────────────────────────┐        │   sessions (비공개) 사진·영상     │
│ 손님 폰 브라우저            │        │   frames   (공개)  프레임 PNG    │
│ Vercel 정적 페이지          │ ─────▶ │                                │
│ /s?id=<촬영ID>             │ 조회    │ DB                              │
└───────────────────────────┘        │   sessions, frames, settings    │
                                     │ pg_cron  매시 정각 cleanup 호출   │
                                     └────────────────────────────────┘
```

### 왜 이렇게 나눴나

- **APK에 비밀키를 넣지 않는다.** APK는 누구나 풀어볼 수 있다. 태블릿은 Edge Function에 "업로드해도 되나"를 묻고, 업로드 허가 URL(2시간 유효, Supabase 고정값)만 받는다. 오프라인으로 2시간이 지나면 같은 촬영 ID로 새 URL을 다시 받는다.
- **사진 저장소는 비공개.** 손님 페이지는 `get-session`에 촬영 ID를 보내고, 함수가 24시간이 지났는지 확인한 뒤 10분짜리 다운로드 URL을 내준다. 서버 파일 삭제가 최대 1시간 늦어도 손님 쪽에서는 정확히 24시간에 막힌다.
- **Supabase는 HTML을 직접 띄우지 않는다.** 그래서 손님 페이지만 Vercel에 둔다.

## 3. 데이터

### 테이블

정의 원본은 `supabase/migrations/20260917000000_photobooth_schema.sql`.

| 테이블 | 핵심 컬럼 |
|---|---|
| `sessions` | `id`(태블릿이 생성한 UUID), `device_id`, `frame_id`, `photo_path`, `video_path`, `created_at`, `uploaded_at`, `expires_at`(= 업로드 시각 + 24시간, 함수가 기록), `deleted_at` |
| `frames` | `id`, `name`(1~30자), `layout`(vertical/grid), `path`, `is_active`, `created_at` |
| `admin_settings` | 한 줄짜리. `pin_hash`(bcrypt), `failed_attempts`, `locked_until` |

`uploaded_at`과 `expires_at`은 항상 함께 채워지도록 제약을 걸었다. DB 함수 3개(`set_admin_pin`, `check_admin_pin`, `sessions_to_purge`)는 anon에서 실행 권한을 회수했다.

세 테이블 모두 RLS를 켜고 정책은 두지 않는다. 모든 접근은 Edge Function(서비스 권한)을 거친다.

### 저장 경로

| 버킷 | 경로 | 공개 | 삭제 |
|---|---|---|---|
| `sessions` | `{id}/photo.jpg`, `{id}/timelapse.mp4` | 비공개 | 업로드 후 24시간 + 최대 1시간 |
| `frames` | `{frame_id}.png` | 공개 읽기 | 삭제하지 않음 |

### 운영 계정

- 포토부스 전용 Supabase 계정(공동 운영자 명의)에 프로젝트 1개, 지역 Seoul
- 기존 계정은 **Developer 역할로 초대**. Owner·Admin이면 기존 계정의 무료 프로젝트 2개 한도에 합산되어 생성이 막힘
- 무료 한도는 조직 단위로 공유되므로, 포토부스 외 프로젝트를 이 조직에 만들지 않는다

### 용량 계산 (무료 플랜: 다운로드 월 5GB, 저장 1GB)

- 사진 약 0.4MB + 타임랩스 약 1.5MB(720×960, 2Mbps, 약 6초) = **한 팀당 약 2MB**
- 손님 페이지는 파일을 **한 번만 받아** 미리보기와 저장에 같이 쓴다. 미리보기 따로, 저장 따로 받으면 다운로드가 두 배가 된다
- 월 500팀 × 2MB ≈ 1GB 다운로드, 여러 번 열어도 2GB 이내
- 저장 공간은 매시간 비워지므로 동시에 쌓이는 양은 하루치 이하 (하루 100팀 ≈ 200MB)

### 일시정지 대응

무료 프로젝트는 1주일간 요청이 없으면 일시정지된다.

- 태블릿 앱이 켜져 있으면 6시간마다 `list-frames`를 호출해 활동을 유지
- 행사 전 점검 목록에 "대시보드에서 프로젝트 상태 확인"을 넣는다
- 일시정지 상태에서 업로드가 실패하면 대기열에 남고, 복구 후 자동 업로드된다

## 4. 흐름

### 4.1 촬영 (태블릿)

1. 대기 화면 → 프레임 선택 (세로 4컷 / 바둑판 구분 표시)
2. 촬영 ID(UUID) 생성, 타임랩스 녹화 시작
3. 6컷 촬영. 첫 컷 3초, 이후 2초 카운트다운
4. 타임랩스 녹화 종료
5. 6장 중 4장 선택. 선택 순서 = 프레임 칸 순서. 4장 미만이면 완성 버튼 비활성. 4장을 고른 상태에서 다른 사진을 누르면 바꾸지 않고 "이미 4장을 골랐어요. 빼고 싶은 사진을 먼저 눌러주세요" 안내
6. 사진 합성, 타임랩스 인코딩
7. **업로드와 상관없이 즉시 QR 표시** (`https://<vercel>/s?id=<촬영ID>`)
8. 백그라운드 업로드 대기열에 추가
9. 60초 무조작 시 대기 화면으로 복귀

### 4.2 업로드 (태블릿, 백그라운드)

1. `create-upload(id, device_id, frame_id)` → 사진·영상 업로드 허가 URL 2개
2. 두 파일 업로드
3. `complete-upload(id)` → `uploaded_at` 기록
4. 실패하면 기기 저장소에 파일과 촬영 정보 보관
5. 네트워크 복구 감지 시, 그리고 30초마다 대기열 재시도 (최대 대기 24시간, 넘으면 폐기)

앱이 꺼졌다 켜져도 대기열은 남는다.

### 4.3 손님 페이지 (Vercel)

`get-session(id)` 응답에 따라 네 가지 상태만 있다.

| 상태 | 조건 | 화면 |
|---|---|---|
| 준비 중 | 레코드 없음 또는 `uploaded_at` 없음 | "사진을 올리는 중이에요. 잠시 후 새로고침해주세요." + 새로고침 버튼. 10초마다 자동 재확인 |
| 받기 가능 | 24시간 이내 | 사진, 타임랩스, 남은 시간, 저장 버튼 2개 |
| 만료 | 24시간 경과 | "보관 기간 24시간이 지나 사진이 삭제되었어요." |
| 없음 | 형식이 틀린 ID | "QR 주소가 올바르지 않아요. 부스에서 다시 찍어주세요." |

- 남은 시간: `expires_at` 기준 1분 단위 갱신, 1시간 미만이면 분 단위로 표시
- 저장: 안드로이드는 파일 다운로드, 아이폰은 공유창(Web Share API), 둘 다 안 되면 길게 눌러 저장 안내

### 4.4 삭제

- `pg_cron`이 매시 정각 `cleanup` 함수 호출
- `uploaded_at < now() - 24h and deleted_at is null` 인 세션의 파일을 Storage API로 삭제 후 `deleted_at` 기록
- 업로드가 끝나지 않은 채 48시간이 지난 레코드도 정리

DB에서 `storage.objects` 행을 직접 지우면 실제 파일이 남으므로 반드시 Storage API로 지운다.

### 4.5 프레임 등록 (태블릿 관리자 모드)

1. 대기 화면 오른쪽 위 모서리를 3초 길게 누름
2. PIN 4자리 입력 → `manage-frames`가 서버에서 해시 비교 (등록·숨기기 등 모든 동작마다 다시 확인). 5회 틀리면 10분 잠금
3. 갤러리에서 PNG 선택, 이름 입력, 레이아웃 선택
4. 앱에서 검사
   - PNG가 아니면 거절: "PNG 파일만 등록할 수 있어요"
   - 비율이 규격과 1% 넘게 다르면 거절: "세로 4컷은 591×1772 비율이어야 해요. 지금 파일은 1000×1500이에요"
   - 규격 사진 칸 중앙이 투명하지 않으면 거절: "3번째 사진 칸이 투명하지 않아요"
   - 비율이 맞으면 규격 크기로 축소·확대
5. 업로드 → `frames` 레코드 생성
6. 모든 태블릿은 대기 화면 진입 시 `list-frames`로 목록 갱신, PNG는 기기에 캐시 (오프라인에서도 촬영 가능)
7. 목록에서 프레임 숨기기 가능 (`is_active = false`). 파일은 지우지 않음

관리자 모드는 인터넷 연결이 필요하다. 끊겨 있으면 "프레임 등록은 인터넷 연결이 필요해요"를 표시한다.

## 5. 타임랩스

- 촬영 시작부터 6컷 종료까지(약 16초) 카메라 화면을 **초당 10장** 샘플링 (720×960, 좌우 반전, 하단에 행사명)
- **기본 경로 (WebCodecs):** 샘플한 프레임을 곧바로 기기의 H.264 하드웨어 인코더에 넣으면서 타임스탬프를 30fps 간격으로 붙인다. 초당 10장을 30fps로 재생하므로 3배속이 되고, 두 번 인코딩하지 않는다. 결과는 항상 MP4 (아이폰에서 재생·저장 가능)
- **대체 경로 (구형 WebView):** 프레임을 JPEG로 모았다가 MediaRecorder로 다시 녹화. mp4가 안 되면 webm
- 비트레이트 2Mbps, 최대 240프레임(8초)
- 인코더가 밀리면 프레임을 건너뛰고 메모리에 쌓지 않는다
- 인코딩은 손님이 4장을 고르는 동안 진행되고, 완성 화면은 기다리지 않는다
- 실패하면 사진만 업로드하고 손님 페이지에서 영상 영역을 숨긴다

처음 설계한 "프레임마다 JPEG로 저장 후 재생 녹화" 방식은 테스트에서 JPEG 인코딩이 밀려 3초에 2장만 잡히는 경우가 확인되어 대체 경로로만 남겼다.

## 6. 디자인

### 방향

인화된 사진이 놓인 흰 테이블. 화면에서 색이 있는 것은 사진뿐이다.

### 토큰

| 이름 | 값 | 쓰임 |
|---|---|---|
| paper | `#FFFFFF` | 배경 |
| surface | `#F2F3F4` | 카메라 주변, 빈 칸 |
| line | `#D9DCE0` | 구분선, 빈 칸 테두리 |
| muted | `#6B7078` | 보조 안내 |
| ink | `#000000` | 제목, 주요 버튼, 선택 번호 |

### 서체

Wanted Sans 한 가지. 카운트다운 숫자는 화면 높이의 약 절반 크기로 크게 쓴다. 안내는 짧은 한국어 문장만 쓰고 영문 대문자 라벨은 쓰지 않는다.

### 형태 규칙

- 사진·프레임: 모서리 0 (인화지)
- 누르는 버튼: 완전히 둥글게
- 그림자는 완성 화면의 결과 사진 한 곳에만
- 터치 영역 최소 56px

### 움직임

강조는 한 곳만. 완성 화면에서 결과 사진이 옅은 상태에서 1.2초 동안 선명해지는 등장 연출. 나머지 화면 전환은 150ms 이하 페이드만 쓰고, 동작 줄이기 설정을 따르면 연출도 끈다.

### 문구 원칙

- 버튼은 누르면 일어나는 일 그대로: "이 4장으로 완성", "사진 저장", "영상 저장", "처음으로"
- 오류는 무엇이 잘못됐고 무엇을 하면 되는지: 사과하지 않는다

## 7. APK

- Capacitor 안드로이드 프로젝트, 앱 ID는 구현 시 정함
- 권한: 카메라, 인터넷, 네트워크 상태
- 사용 플러그인: Filesystem(업로드 대기열·프레임 캐시), Preferences(기기 ID), Network(복구 감지)
- 키오스크 동작: 화면 꺼짐 방지, 세로 고정, 전체 화면
- 빌드 산출물을 GitHub Releases에 올리고, 설치 안내는 README에 "출처를 알 수 없는 앱 허용" 절차 포함
- 업데이트: 새 APK를 같은 방식으로 덮어 설치 (서명 키를 잃어버리면 업데이트 설치가 안 되므로 키 보관 필수)

## 8. 보안

| 위험 | 대응 |
|---|---|
| APK에서 키 추출 | 공개 키(anon)만 포함. 업로드는 허가 URL로만 가능 |
| 아무나 업로드 허가 요청 | 기기 ID당 분당 요청 수 제한, 파일 크기 제한(사진 5MB, 영상 20MB), MIME 제한 |
| 촬영 ID 추측 | UUID v4, 목록 조회 기능 없음 |
| 만료 후 파일 접근 | 비공개 버킷 + `get-session`에서 24시간 검사 + 10분짜리 URL |
| PIN 무차별 대입 | 서버 검증, 5회 실패 시 10분 잠금 |

## 9. 검증

구현 후 실기기에서 아래를 모두 통과해야 완료로 본다.

1. 세로 태블릿에서 카메라 좌우 반전 정상
2. 6장 촬영 중 끊김 없음
3. 4장 선택 순서대로 프레임 칸에 들어감
4. 타임랩스가 5~7초이고 실제로 빨리감기로 재생됨
5. QR → 손님 폰에서 사진·영상 저장 (안드로이드, 아이폰 각 1회)
6. 비행기 모드로 촬영 → QR 페이지 "올리는 중" → 네트워크 복구 후 자동 업로드 → 페이지에서 받기 가능
7. 앱 강제 종료 후 재실행해도 대기열 유지
8. 규격이 다른 PNG, 칸이 막힌 PNG 등록 시 이유가 표시되고 거절됨
9. 태블릿 A에서 등록한 프레임이 태블릿 B에 나타남
10. `uploaded_at`을 25시간 전으로 바꾸면 손님 페이지 "만료", 다음 정각에 파일 삭제 확인
